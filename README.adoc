== What you'll build

You'll build a simple web application with Angular CLI, a tool for Angular development. You'll create an application with search and edit features.

== What you'll need

* About 30 minutes.
* A favorite text editor or IDE. I recommend https://www.jetbrains.com/idea/[IntelliJ IDEA].
* http://nodejs.org/[Node.js] 22.22.3+, 24.15+, or 26+ and npm installed.
* https://github.com/angular/angular-cli[Angular CLI] installed.

If you don't have Angular CLI installed, install it:

----
npm install -g @angular/cli@22
----

NOTE: IntelliJ IDEA Ultimate Edition has the best support for TypeScript. If you'd rather not pay for your IDE, checkout https://code.visualstudio.com/[Visual Studio Code].

== Create a new Angular project

Create a new project using the `ng new` command:

----
ng new ng-demo
----

When prompted for the stylesheet system, choose "`CSS`" (the default). Accept the default (No) for SSR (Server-Side Rendering) and SSG (Static Site Generation). When asked which AI tools Angular should integrate with, select "`None`" (or the one you use).

This will create a `ng-demo` project and run `npm install` in it. It takes about a minute to complete, but will vary based on your internet connection speed.

If you've used previous versions of Angular, you'll notice a few differences in the generated project:

* Files no longer have a type suffix. The root component lives in `app.ts` and its class is named `App` (instead of `app.component.ts` and `AppComponent`).
* Applications are zoneless by default. There's no `zone.js` dependency and change detection is driven by signals and template events.
* Components use `OnPush` change detection by default.
* Unit tests run with https://vitest.dev/[Vitest] instead of Karma and Jasmine.
* Static files like images and JSON go in the `public` directory instead of `src/assets`.

You can see the version of Angular CLI you're using with the `ng version` command.

[source,typescript]
.src/app/shared/search/search-service.ts
----
import { inject, Service } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

@Service()
export class SearchService {
  private readonly http = inject(HttpClient);

  getAll(): Observable<Person[]> {
    return this.http.get<Person[]>('data/people.json');
  }
}

export class Address {
  street: string;
  city: string;
  state: string;
  zip: string;

  constructor(obj?: any) {
    this.street = obj?.street || null;
    this.city = obj?.city || null;
    this.state = obj?.state || null;
    this.zip = obj?.zip || null;
  }
}

export class Person {
  id: number;
  name: string;
  phone: string;
  address: Address;

  constructor(obj?: any) {
    this.id = obj?.id || null;
    this.name = obj?.name || null;
    this.phone = obj?.phone || null;
    this.address = obj?.address || null;
  }
}
----

The `@Service()` decorator is new in Angular 22. Like `@Injectable({providedIn: 'root'})`, it makes the service available everywhere in your app. Unlike `@Injectable`, it doesn't support constructor injection. If you try to inject `HttpClient` with `constructor(private http: HttpClient) {}`, you'll get an error:

----
✘ [ERROR] NG2028: @Service class cannot use constructor dependency injection. Use the `inject` function instead.
----

[source,typescript]
.src/app/shared/index.ts
----

----

The reason for creating this file is so you can import multiple classes on a single line rather than having to import each individual class on separate lines.

In previous versions of Angular, you'd need to add `provideHttpClient()` to `app.config.ts` at this point. In Angular 22, `HttpClient` is provided in the root injector, so it works without any configuration.

If you click the search button now, you'll notice that nothing happens. However, if you type something in the search box, the results appear!

This is because Angular 22 apps are zoneless and components use `OnPush` change detection. Angular no longer knows that something changed when an HTTP response arrives and you assign it to a regular property. It only updates the view after the next event, like a keystroke.

The fix is to use a https://angular.dev/guide/signals[signal]. Signals tell Angular exactly when their value changes. Change `searchResults` to a signal and call `set()` when the data arrives.

[source,typescript]
.src/app/search/search.ts
----
import { Component, inject, signal } from '@angular/core';
...

export class Search {
  query: string | undefined;
  searchResults = signal<Person[]>([]);
  private readonly searchService = inject(SearchService);

  search(): void {
    this.searchService.getAll().subscribe({
      next: (data: Person[]) => {
        this.searchResults.set(data);
      },
      error: error => console.log(error)
    });
  }
}
----

In `search.html`, read the signal's value by calling it.

[source,html]
.src/app/search/search.html
----
<pre>{{searchResults() | json}}</pre>
----

But wait, you still don't have search functionality! To add a search feature, add a `search()` method to `SearchService`. It returns the people whose name, phone, or address contains the query.

[source,typescript]
.src/app/shared/search/search-service.ts
----
import { map, Observable } from 'rxjs';
...

  search(q: string): Observable<Person[]> {
    if (!q || q === '*') {
      q = '';
    } else {
      q = q.toLowerCase();
    }
    return this.getAll().pipe(
      map((data: Person[]) => data
        .filter((item: Person) => this.matches(item, q)))
    );
  }

  private matches(person: Person, q: string): boolean {
    const values = [person.name, person.phone, ...Object.values(person.address ?? {})];
    return values.some(value => value?.toLowerCase().includes(q));
  }
----

Then refactor `Search` to call this method with its `query` variable.

[source,typescript]
.src/app/search/search.ts
----
search(): void {
  this.searchService.search(this.query).subscribe({
    next: (data: Person[]) => {
      this.searchResults.set(data);
    },
    error: error => console.log(error)
  });
}
----

This won't compile right away.

[source,shell]
----
✘ [ERROR] TS2345: Argument of type 'string | undefined' is not assignable to parameter of type 'string'.
  Type 'undefined' is not assignable to type 'string'. [plugin angular-compiler]
----

Since `query` will always be assigned (even if it's empty), change its variable declaration to:

[source,typescript]
----
query!: string; // query: string = ''; will also work
----

This is called a https://www.typescriptlang.org/docs/handbook/release-notes/typescript-2-7.html#definite-assignment-assertions[definite assignment assertion]. It's a way to tell TypeScript "`I know what I'm doing, the variable will be assigned.`"

TIP: You don't need to make `query` a signal because it only changes when you type in the input. Template events like typing and clicking still trigger change detection.

Now search results will be filtered by the query value you type in.

[source,typescript]
.src/app/edit/edit.ts
----
import { Component, inject, OnDestroy, OnInit, signal } from '@angular/core';
import { ActivatedRoute, Router } from '@angular/router';
import { FormsModule } from '@angular/forms';
import { Subscription } from 'rxjs';
import { Person, SearchService } from '../shared';

@Component({
  imports: [FormsModule],
  selector: 'app-edit',
  styleUrl: './edit.css',
  templateUrl: './edit.html',
})
export class Edit implements OnInit, OnDestroy {
  person = signal<Person | undefined>(undefined);
  sub!: Subscription;
  private readonly route = inject(ActivatedRoute);
  private readonly router = inject(Router);
  private readonly service = inject(SearchService);

  ngOnInit(): void {
    this.sub = this.route.params.subscribe(params => {
      const id = +params['id']; // (+) converts string 'id' to a number
      this.service.get(id).subscribe(person => {
        if (person) {
          this.person.set(person);
        } else {
          this.gotoList();
        }
      });
    });
  }

  ngOnDestroy(): void {
    if (this.sub) {
      this.sub.unsubscribe();
    }
  }

  async cancel() {
    await this.router.navigate(['/search']);
  }

  async save() {
    this.service.save(this.person()!);
    await this.gotoList();
  }

  async gotoList() {
    const person = this.person();
    if (person) {
      await this.router.navigate(['/search', {term: person.name}]);
    } else {
      await this.router.navigate(['/search']);
    }
  }
}
----

Modify `SearchService` to contain functions for finding a person by their id and saving them. While you're in there, modify the `search()` method to be aware of updated objects in `localStorage`.

[source,typescript]
.src/app/shared/search/search-service.ts
----
search(q: string): Observable<Person[]> {
  if (!q || q === '*') {
    q = '';
  } else {
    q = q.toLowerCase();
  }
  return this.getAll().pipe(
    map((data: Person[]) => data
      .map((item: Person) => !!localStorage['person' + item.id] ?
        JSON.parse(localStorage['person' + item.id]) : item)
      .filter((item: Person) => this.matches(item, q))
    ));
}

get(id: number): Observable<Person> {
  return this.getAll().pipe(map((all: Person[]) => {
    if (localStorage['person' + id]) {
      return JSON.parse(localStorage['person' + id]);
    }
    return all.find((e: Person) => e.id === id);
  }));
}

save(person: Person) {
  localStorage['person' + person.id] = JSON.stringify(person);
}
----

----
import { Component, inject, OnDestroy, OnInit, signal } from '@angular/core';

export class Search implements OnInit, OnDestroy {
  ...

  ngOnDestroy(): void {
    if (this.sub) {
      this.sub.unsubscribe();
    }
  }
}
----

=== Form Validation

One thing you might notice is you can clear any input element in the form and save it. At the very least, the `name` field should be required. Otherwise, there's nothing to click on in the search results.

To make name required, modify `edit.html` to add a `required` attribute to the name `<input>` and bind it to Angular's validation with `#name="ngModel"`. Add a `<div>` next to the field to display an error message when validation fails.

[source,html]
.src/app/edit/edit.html
----
<input [(ngModel)]="person.name" name="name" id="name" placeholder="Name" required #name="ngModel"/>
<div [hidden]="name.valid || name.pristine" style="color: red">
  Name is required
</div>
----

You'll also need to wrap everything in a `<form>` element. Add `<form>` after the `<h3>` tag and close it before the closing `}`. You'll also need to add an `(ngSubmit)` handler to the form, give it the name of `editForm`, and change the save button to be a regular submit button that's disabled when the form is invalid. Give the cancel button `type="button"`, too. Buttons in a form default to `type="submit"`, so without it, clicking *Cancel* would submit the form and save your changes.

[source,html]
.src/app/edit/edit.html
----
<h3>{{person.name}}</h3>
<form (ngSubmit)="save()" #editForm="ngForm">
  ...
  <button type="submit" id="save" [disabled]="!editForm.form.valid">Save</button>
  <button type="button" (click)="cancel()" id="cancel">Cancel</button>
</form>
----

== Deploy to Netlify

This section shows you how to deploy your Angular app to https://www.netlify.com[Netlify]. Netlify detects Angular projects automatically, gives you HTTPS and a global CDN, and has a free plan that's plenty for an app like this.

Create a `netlify.toml` file in your project's root directory. It tells Netlify how to build your app and where the files are, sends every route to `index.html` so Angular's router can handle it, and adds security headers to every response.

[source,toml]
.netlify.toml
----
[build]
  command = "npm run build"
  publish = "dist/ng-demo/browser"

[build.environment]
  NODE_VERSION = "24"

# Send all routes to index.html so Angular's router can handle them
[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200

[[headers]]
  for = "/*"
  [headers.values]
    Content-Security-Policy = "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; frame-ancestors 'none'"
    Referrer-Policy = "strict-origin-when-cross-origin"
    X-Content-Type-Options = "nosniff"
    X-Frame-Options = "DENY"
    Permissions-Policy = "geolocation=(), microphone=(), camera=()"
----

Netlify serves your site over HTTPS and adds a `Strict-Transport-Security` header for you, so you don't need to add one.

TIP: The content security policy (CSP) only allows scripts, styles, images, and fonts from your own site. Angular doesn't need `'unsafe-eval'`, but it does need `'unsafe-inline'` for styles, because it adds component styles to the page in `<style>` elements.

The CSP blocks inline scripts, though, and Angular's production build adds one by default. It inlines your app's critical CSS in `index.html`, loads the rest of your global styles with `media="print"`, and adds an inline script that switches them to `media="all"`. Turn off `inlineCritical` for production builds in `angular.json` so your deployed app gets all of its global styles.

[source,json]
.angular.json
----
"production": {
  ...
  "outputHashing": "all",
  "optimization": {
    "styles": {
      "inlineCritical": false
    }
  }
},
----

You can test this configuration locally with the https://docs.netlify.com/cli/get-started/[Netlify CLI]. The `netlify serve` command builds your app and serves it with the same redirects and headers that Netlify uses.

[source,shell]
----
npx netlify-cli@27.12.1 serve
----

Open `http://localhost:8888/search` and make sure everything works. The Netlify CLI adds its local `.netlify` folder to your `.gitignore` the first time you run it.

https://app.netlify.com/signup[Create a Netlify account], then log in with the Netlify CLI.

[source,shell]
----
npx netlify-cli@27.12.1 login
----

Deploy your app to a new site. Replace `<your-site-name>` with a name that's unique on Netlify.

[source,shell]
----
npx netlify-cli@27.12.1 deploy --site-name <your-site-name>
----

This creates a draft deploy with its own URL, so you can check it before your users see it. When you're happy, deploy it to production.

[source,shell]
----
npx netlify-cli@27.12.1 deploy --prod
----

Your app will be live at `\https://<your-site-name>.netlify.app`. Try its URL on https://securityheaders.com[securityheaders.com] to be pleasantly surprised.

TIP: To deploy every time you push to GitHub, run `npx netlify-cli@27.12.1 init` and choose to connect your repository. Netlify will build and deploy your `main` branch automatically, and create deploy previews for your pull requests.
